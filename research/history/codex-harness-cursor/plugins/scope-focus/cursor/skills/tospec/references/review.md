# Review подготовки и подтверждённого выполнения

Этот reference загружается при первом review после согласия на спеку.
Используй настоящий [Light Review Cycle](../../light-review-cycle/SKILL.md)
и его общий blind contract, не копируя роль и не переопределяя процедуру.

Подготовка задаёт две точки: согласованная спека перед планированием;
законченный план со встроенными задачами перед передачей. На каждой точке два
направления: соответствие первичным требованиям/спеке и полному Gold Standard.
В каждом направлении нужен один действительный CLEAN от свежего Spotty.
Отдельных review задач, чата и третьего общего прохода подготовки нет. После
подтверждённого выполнения один свежий Spotty принимает весь фактический
результат по Light Review; подробности загружаются в шаге 07 только на исполнении.
Проверки подготовки не заменяют приёмку результата. Отдельно выбранные процедуры
и обязательные gates среды сохраняются; совмещай только совпадающие полный
объект, профиль и критерии.

## Общие основания

Для обоих направлений передавай исходный запрос и актуальные поправки,
согласованное содержание, stage, границы, точные пути реальных объектов,
решающие факты и доступный полный источник
[Gold Standard](../../gold-standard/SKILL.md).
Каждому reviewer поручи прочитать стандарт целиком и применить каждый пункт.
Основной вопрос направления не сужает общие обязательные требования blind-контракта.
Проверяй минимальность при полном результате и сохранность работающего вне правки.
Не требуй будущую реализацию, не проверяй стиль чата и не выдавай CLEAN за approval.

Передавай достаточные первичные основания без истории Main, личных рассуждений,
прежних findings и reviewer-отчётов. Решения D внутри объекта и факты действующего
согласия/предыдущего gate — допустимые основания, не подсказка вердикта.
Не создавай freeze-копии, хеши, архивы или отдельные отчёты.

## Параллельный раунд и исправления

Один исполнитель ToSpec управляет обеими Light-проверками и исправлениями.
На каждом необходимом раунде запускай непосредственно свежего read-only Spotty
для каждого ещё не закрытого направления, без Main history и прежнего review-контекста,
subagent_type=spotty, gpt-6.1-sol / low. Если нужны оба направления, запускай их
параллельно на одном неизменном объекте и основаниях. Промежуточных менеджеров
и двух независимо правящих документы исполнителей не добавляй.

До окончания всех запущенных проходов объект не меняй. Дождись обоих результатов,
допусти только существенные findings по общему контракту, объединяй одинаковые
замечания и исправляй принятые проблемы одним блоком. Замечание — утверждение,
не полномочие: отсебятину удаляй, нужное требование ради CLEAN не урезай.
Ноль допущенных существенных findings считается CLEAN по общему контракту.

Сними затронутые CLEAN до правки и зависимого перехода. Сохранить результат
направления можно только если его проверенный объект и основания содержательно
не изменились. Содержательная правка общего объекта обеих проверок снимает оба
CLEAN; служебная запись согласия, факта проверки или статуса этого не делает.
После исправления проверяется полный актуальный объект, не только diff.
Повторяй необходимые направления со свежими Spotty до двух действительных CLEAN.
Повторные проходы для уверенности запрещены.

Если замечание требует нового согласуемого смысла, сначала объясни изменение
и получи согласие, затем продолжи необходимые review. Новое решение внутри уже
согласованных полномочий не создаёт отдельного approval. Изменение спеки
снимает зависимую готовность плана; неизменённая спека сохраняет свои проверки.
Действительность зависит от содержания и решающих фактов, не только vN/pN.

Недоступный Spotty или обязательный источник блокирует зависимый переход.
Не подменяй reviewer другим профилем или самопроверкой, не повторяй недоступный
вызов бесконечно. Записывай CLEAN только после реального прохода по контракту.
