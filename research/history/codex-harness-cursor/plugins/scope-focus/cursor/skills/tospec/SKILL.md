# ToSpec

Один skill с деревом обычных вложенных инструкций для любой задачи, включая
аналитическую или документную без рабочего каталога. Подготовка даёт spec.md
и plan.md со встроенными задачами; решение объясняется в чате. Отдельное `+++`
после готового плана подтверждает его выполнение по описанной процедуре.

## Обязательное основание

До работы прочитай полностью [Gold Standard](../gold-standard/SKILL.md).
Применяй каждый пункт ко всем действиям, решениям, документам и переходам;
не заменяй источник выжимкой. Уже доступный актуальный полный текст повторно
не читай; после потери контекста восстанови его до зависимой работы.
Для чата действует [Clear Communication](../clear-communication/SKILL.md):
читай источник только если полный актуальный текст ещё не доступен.

Выбирай самый простой достаточный путь при полном результате. Качество не
разрешает расширять задачу, минимальность — терять требования или работающее
поведение вне заказанного изменения. Эффективность оценивай по источникам
и логике; существенное неизвестное разрешай минимальным безопасным опытом по
шагу разведки, когда источников недостаточно. Различай оценку и реальное
наблюдение; не обещай измеренный без замера или глобальный оптимум.

## Загрузка по этапам

Основной файл задаёт маршрут и общие границы; подробности находятся в шагах,
references и шаблонах. Вложенные файлы не являются самостоятельными skills.
Открывай только текущий шаг и указанные в нём необходимые материалы. Следующий
шаг загружай после выполнения условия выхода текущего, без вопроса о продолжении.
Не вычитывай дерево заранее и не читай шаблон плана во время подготовки спеки.

1. [Разведка](steps/01-research.md).
2. [Спецификация](steps/02-spec.md).
3. [Объяснение решения и согласование](steps/03-approve.md).
4. [Два параллельных Light Review спеки](steps/04-spec-review.md).
5. [План со встроенными задачами](steps/05-plan.md).
6. [Два параллельных Light Review плана и готовность](steps/06-plan-review.md).
7. [Выполнение](steps/07-execute.md) — только после отдельного `+++`.

Это единственный общий маршрут; шаги не ведут его независимую копию. Объединяй
чтение текущего шага и уже известных нужных ему материалов. Актуальные
загруженные инструкции переиспользуй; после потери контекста восстанавливай
только необходимые для продолжения источники. Не создавай загрузчик, кеш,
движок состояний, hooks или новые skills для этапов.

При будущей доработке сверяй в обе стороны весь прямо затронутый контракт:
основной файл, зависимые шаги, references, шаблоны, UI и связанную документацию.
Согласуй имена, ссылки, входы, условия выхода, полномочия и основания готовности
чтением и логикой. Не добавляй для этого отдельный enforcement или workflow.

## Полномочия и готовность

Пользователь согласует весь текущий смысл спеки. Только после согласия начинаются
два её review; только после двух действительных CLEAN — подготовка плана.
План и его технические решения внутри спеки агент готовит самостоятельно,
без отдельного approval. Новый результат, scope, стоимость, доступ, приватность
или иное изменение согласованного условия возвращается к спеке и согласованию.

Две пары review подготовки — явно выбранная процедура ToSpec: одна после согласия на спеку,
другая после завершения плана. Каждая требует два действительных CLEAN по своим
направлениям. Reviewer проверяют объекты задачи, не стиль пользовательского
сообщения. CLEAN не заменяет согласие и не гарантирует безошибочность.

Храни документы подготовки и материалы исследования только в точном OS tmp
workspace текущей задачи; отдельно нужный Notebook использует собственное OS tmp
пространство по своему skill. До подтверждения не изменяй целевые объекты; разрешены
чтение, временные документы и необходимый изолированный discovery по шагу 01.
Явные запреты и обязательная пользовательская методика сохраняются. Выбор
подготовки не включает execution Goal или итоговый review исполнения. Notebook
выбирается по полезному состоянию согласно общему стандарту и не дублирует
primary документы. Готовые spec/plan сохраняются для исполнения. Подробности
выполнения загружаются после подтверждения. Отдельное `+++` выбирает Goal,
выполнение по полному стандарту и один Light Review результата. Notebook и
очистка применяются по общей условной политике; автоматическая очистка касается
только расходных материалов текущей завершённой задачи. Другие режимы не включаются;
действующий Lunatron сохраняет собственный контракт.

Согласие, основания, ревизии, статусы и проверки хранятся в двух документах,
без реестра, хешей, копий или архива. Готовность требует согласия на текущий смысл
и действительных обеих пар review. При содержательной правке или изменении
решающего факта сними затронутые CLEAN и готовность до зависимого перехода.
Номер документа сам по себе не доказывает актуальность согласия или проверки.
Без обязательного ответа, источника или Spotty останови зависимый переход.

Сокращение подтверждения — только целое пользовательское сообщение `+++`;
внешние пробелы допустимы, цитата, код или часть большего сообщения не подходят.
Оно относится к однозначному текущему готовому плану. Не ищи похожий или последний
workspace; при недостающей связи запроси точный план. Повторное подтверждение
продолжает то же выполнение либо сообщает достигнутый результат, без второго
Goal, Notebook или повторения операций. Готовность сама по себе не разрешает
выполнение; материалы сохраняются до его завершения и приёмки.
