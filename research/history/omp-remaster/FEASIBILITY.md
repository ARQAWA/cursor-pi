# Stage 3: public API feasibility

This file records which Cursor behaviors stock OMP lets an extension reproduce exactly, through which public API, and what was observed. It ships no Cursor prompt, tool or subagent; stages 4–5 implemented the prompts and the basic tools, and PLAN.md stages 6–14 planned the rest.

## Method

Source: OMP 18.10.0 (`b83200eb`); runs: installed OMP 18.10.1. A throwaway probe extension (not part of this branch) used only the factory's `ExtensionAPI`, the handler `ctx`, the injected `pi.pi` SDK exports, type imports and Node built-ins. It registered all eight captured Cursor main-tool definitions from `reference/cursor/prompts/tools/toolset-bb31022a144f.json` as stubs plus test tools, inserted marker context messages, and a recorder loaded last wrote every outgoing provider payload to a file. Every run used `--no-extensions --no-skills --no-rules --no-lsp --no-title --thinking low --system-prompt ''`. Cursor scenarios come from `reference/cursor/`: REPORT.md, `runs-2026-10-16/` (Sol and GPT-5.5 calls and items), T3 and T4. The payload files stayed on the development machine because they carry account and installation identifiers. In the Evidence column "req N" is the Nth recorded request of the parent session of that run; child and fork requests are named "child req N" and "fork req N" in their own order.

## Child sessions and the stage 2 criterion

The stage 2 criterion covers main and child-session preparation. The package itself still starts no child session, because OMP's `task` tool is off and the package registers only Cursor's five basic tools, so the child half of that criterion is not met by the package. It is covered only by the probe evidence in row A3 and by stage 10, which adds the package's subagents that way and checks their requests.

## Consequences for later stages

- Stage 4 builds the context, including the `<timestamp>`/`<user_query>` wrapper, in `context`, and sends an empty system prompt so OMP adds no reminder; on Anthropic, where developer messages become `user` (A2a), it sends the prompt as the system prompt and removes OMP's reminder from the request; Codex runs need the SSE transport for full-history requests.
- Stage 5 uses internal tool names where they collide with OMP built-ins and, in OpenAI Responses requests, replaces tool definitions with the reference entries and rewrites tool outputs in `before_provider_request`.
- Stages 10–11 create children with `createAgentSession` as in A3 and deliver background completions as `followUp` user messages. That delivery is shown in RPC mode only; interactive mode is unverified.

## Blockers and open points

No scenario needed a private import or an OMP patch. Blockers: the developer role on Anthropic and the other Anthropic subscription wire changes (A2a, X1); the unproven OpenAI API developer role (A2o); AwaitShell pattern and timeout returns not observed (C4, stage 11); the self-fork without the in-flight call and context messages (D3, stage 10). Open: interactive mode was not run for background notifications, and Cursor's own `parallel_tool_calls` value is missing from `reference/` (B4).
