## Алгоритм

Схема одна и та же у всех трёх прогонов. Разница в глубине проверки и в том, как агент реагирует на падение теста.

1. **Перевод задачи в имена.** Агент переводит фразу в идентификаторы: `wallet`, `sync`, `retry`, `attempt`, а также русские слова. Сначала берёт карту репозитория: r1 шаг 1 запустил rg с пустым шаблоном (762 файла). Потом ищет одним шаблоном с синонимами (r1 шаг 2; r3 шаг 1). Пустой результат меняет способ поиска. У r3 шаг 4 glob `superbot_ng/**` ничего не нашёл, вывод: пакет лежит в `src/`. На шаге 5 агент пошёл по именам файлов (`**/*wallet*`).
2. **Поиск образца.** Агент смотрит содержимое `tests/contracts` (r2 шаг 2; r1 шаг 2; r3 шаг 1). Ближайший по имени файл `test_wallet_failure_contracts.py` читается целиком (r1 шаг 4; r2 шаг 4; r3 шаг 2). Соседний `test_wallet_scheduler_contracts.py` тоже читается. Он проверяет SQL и выбор повторов, но не запись времени после ошибки (r1 шаг 5; r3 шаг 3).
3. **Путь значения до источника.** Один rg по именам полей (`next_attempt`, `retry_after`, `record_failure`) даёт цепочку. `store_sync_results.py:40` считает `next_attempt_at = now + timedelta(seconds=max(1, …))`. `store_sync_failure_sql.py` задаёт порядок `$1–$4` (r2 шаг 6; r3 шаг 6). r2 и r3 дошли до `failures.py`, где `WALLET_FAILURE_RETRY_SECONDS = 30` (r2 шаги 8–9; r3 шаг 11). r1 до этого не дошла и взяла 45 с.
4. **Одна правка.** Новая функция вставляется после существующего теста (`@@ -62,6 +62,66 @@` у всех трёх). Используются те же фейки и фиксированное `now`. Аргументы `fetchval` сверяются с SQL-константой (r1 шаг 8; r2 шаг 16; r3 шаг 12). r3 шаг 13 исправила сравнение, которое сравнивало значение с самим собой.
5. **Проверка и реакция на падение.** r1 (шаг 9) и r3 (шаг 14) запускают голый `pytest`. Загрузка conftest падает на `SyntaxError` в `shutdown.py:25`, exit 4, и на этом работа останавливается. r2 (шаг 17) запускает `uv run pytest`: 1 passed, 9 failed. Новый тест падает с `NameError: timedelta` (строка 119). Остальные восемь падают на `No module named '_superbot_native'`, это не связано с правкой. Агент читает трассировку (шаг 19), добавляет импорт (шаг 20 по анализу) и сужает прогон до двух тестов (шаг 21 по анализу).
6. **Diff и отчёт.** Команды `git diff --check` и `git diff` (r1 шаг 10; r3 шаг 15; r2 шаг 23), затем ответ без инструментов. Вывод: агент останавливается, когда тест записан и есть одна проверка или блокер. r1 и r3 останавливаются на блокере. r2 доводит прогон до зелёного.

Общее у всех трёх: один файл, один образец, одна функция-тест, одна правка через ApplyPatch, один вызов инструмента за ответ, без параллельных вызовов. Различия таковы. r2 дошла до источника значения 30 с и запустила тесты через `uv run`. Проект закреплён на Python 3.14.4 (`pyproject.toml`, r2 шаг 15). r1 и r3 приняли ошибку интерпретатора за дефект кода. Вывод: `except A, B:` без скобок допустим в 3.14 (PEP 758), а голый `pytest` шёл на более старом Python. Формулировка r3 «синтаксис Python 2» не подтверждена. Почему r2 выбрала `uv run`, не видно: рассуждение зашифровано, видны только заголовки сводок.

Качество относительно задачи:
- **r2** дала лучший результат. Тест на месте и в стиле файла. Он проверяет `next_attempt_at = now + 30 с` и аргументы SQL, и тест проходит (финальный ответ: 2 теста успешно). Слабости: `store.record_failure` вызывается напрямую, не через `sync_wallet_login`; `30` задано числом, а не константой; проверки `max(1, …)` нет. По анализу шага 22, ruff ругается и на старые строки (11, 15), и на новые (66–95). В ответе это названо «существующими проблемами», что верно только частично.
- **r1**: тест по образцу, но не работает. Вывод по тексту файла: `timedelta` не импортирован (шапка `from datetime import UTC, datetime`, строка 4), значит будет NameError. Тест не запускался. Значение 45 с не взято из кода. Отчёт не упоминает ни дефект, ни то, что тест не запускался.
- **r3**: та же ошибка с `timedelta`. Проверку минимальной задержки 1 с, которую агент обещал в шаге 10, не добавила. Отчёт называет причиной блокировки «синтаксис Python 2» и не упоминает отсутствующий импорт.

## Принципы

- **Сначала образец, потом код.** Ближайший существующий тест читается целиком до того, как пишется новый (r1 шаг 4; r2 шаг 4; r3 шаг 2). Задача сама требует «в стиле существующих тестов».
- **Числа и формулы берутся из кода.** r2 проследила задержку до `WALLET_FAILURE_RETRY_SECONDS = 30` (шаги 6–9), r3 сделала то же (шаг 11). r1 взяла 45 с без проверки. Cursor: «Verify uncertain claims.»
- **Ожидаемое значение берётся из независимого источника.** r3 сначала сравнила значение с самим собой (шаг 12), потом заменила сравнение на `UPDATE_FAILURE_STATE_SQL` (шаг 13).
- **Проверка по риску: запуск, трассировка, исправление, узкий повтор.** r2 шаги 17, 19, 20, 21. Cursor: «implement the requested change, verify it in proportion to risk, and hand off the completed result while a safe, relevant next step remains.»
- **При техническом препятствии сначала пробовать альтернативу.** r1 шаг 9 и r3 шаг 14 остановились после первого exit 4. r2 через `uv run` получила рабочий прогон (шаг 17). Cursor: «Transient technical friction: retry or use a relevant alternative.» Отнесение ошибки интерпретатора к этому классу — вывод.
- **Честность итога.** r1 и r3 сообщили о блокировке, но умолчали, что тест не запускался и содержит NameError. r2 назвала lint-нарушения «существующими», хотя часть из них в новом тесте. Cursor: «When a claim is wrong or risky, say so directly and explain the technical reason.»
- **Параллельные вызовы не использовались.** Во всех трёх прогонах один вызов за ответ (r1 шаги 1–10; r2 шаги 1–23; r3 шаги 1–15), хотя независимые чтения (r1 шаги 4–7) можно было объединить. Cursor: «When possible, parallelize independent tool calls rather than running them sequentially. This reduces round-trip latency and helps you get work done faster.»
- **Поиск и правка выполняются специализированными инструментами.** Все шаги используют rg, Glob, ReadFile или ApplyPatch. Исключение: r2 шаг 12 запустила `rg` внутри Shell вместе с `git log`. Cursor: «When searching for text or files, prefer the dedicated search tools available to you (`rg`, `Glob`) over shell search commands.» и «Try to use `ApplyPatch` for single-file edits».
- **Узкую задачу не передают подагенту.** r2 шаг 1 прочитала описание Subagent, где сказано: «If the query is a narrow or specific question, you should NOT use the Subagent». Подагента она не запускала. Это правило из описания инструмента, а не из системной инструкции.
